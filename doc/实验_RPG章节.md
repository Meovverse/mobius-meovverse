# 实验分支：把后面几章改成「地图走位 + 指引触发」

> 分支：`exp/rpg-探案`（从 main 拉出）。
> 动机：第一章「碑上的名字」是**在地图上操控老吴走动、跟着指引走到目标点触发**；
> 后面几章原来一进来就是"底图 + 文本框 + 资料卡"。美术又补了几张俯视整图，
> 在能复用的地方改成同款 RPG。

## 一、可复用引擎 `src/Game/RpgWalk.cs`

把 `Dev/RPGExplo` 的经验泛化成一个**产品级**走位引擎：
地图可走面 · 四脚占位 · 八向走动（轴分离）· 相机跟随（大图夹边 / 小图居中）·
目标信标（脉冲环 + 亮柱 + 浮标标签）· 顶部指引条 · 走到目标按 Enter 切场。

配置方式：写一个子类（类名=文件名），设 `MapPath / SpawnWorld / Targets / Guidance`，
必要时 `override WalkablePixel`；再加一个薄 `scenes/RpgXxx.tscn`。

  这样**一张铺子图就覆盖了所有铺子章**——不用一章一个场景。
- `map_archive.png` 有大片透明区：已**裁到房间范围**（`map_archive_room.png`，480×440）。
- `ChapterFlow.Label()` 同步映射走位段场景，存档页仍显示正确章名。

## 三、像素级碰撞层

内景是单张 PNG、没有独立碰撞层，运行期按颜色分类会误判家具。做法：
- 离线工具 `tools/walkmask.py`：**颜色分类（暖棕地板）+ 形态学清理 + 手工障碍矩形**
  → 生成 `data/gen/walk_<map>.png`（白=可走）。
- `RpgWalk` **优先读该掩码**（尺寸对不上或缺失才回退颜色分类）。
- 调试图 `data/gen/walkprev_<map>.png`（绿=可走）用于肉眼校对。
- 新增地图：在 `tools/walkmask.py` 的 `MAPS` 里加一条障碍矩形列表即可。
- **坑（Citrate#38）**：木纹/阴影是细线，会打断颜色分类 → 可走面碎成几百块、玩家
  困在小口袋里"走动极其不流畅"。形态学必须用**"闭"（先膨胀后腐蚀）桥接细缝**，
  不能用"开"（会越撕越宽）。办公室闭运算 R=5 后连成一片（最大块 95%）。

## 四、做过的决策（按"最快到可玩"原则）

- **铺子五场共用** → 选**动态目标**（`NextContent()`）方案，一张图覆盖五章，最省事。
- **`Dev/RPGExplo` 的合并** → **暂不合并**。它是 Dev-only 的**回归工具**
  （树 Y-Sort、BFS 自动寻路、到点截图退出、清明版），RpgWalk 是产品走位引擎；
  合并会动到已经跑通的墓园，对"最终可玩"没有收益。两条暂时并存，后续有空再合。

## 五、已知问题 / 下一步

- 颜色分类仍偏粗，掩码靠**手工障碍矩形**校正；家具多起来的图要逐块补矩形。
- 走位段是**纯自由走**，没有寻路（玩家自己走）；墓园那套 BFS 是给自动回归用的。
- `map_shop` 里"工作台"目标点对所有铺子章是同一个；若某章想让玩家走到**不同**的点，
  给 `RpgShop` 加"按 `NextContent()` 选不同目标点"的分支即可。
- 七章（雨夜）暂时没做成走位段（氛围不同，且用的是定景夜图）。
