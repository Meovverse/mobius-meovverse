# 这是程序岗生成的 墓时 · AI 使用说明

> 一句话：**创意与人做，AI 只做"实现加速"。** 本作使用 AI，但范围有限、可审计——
> 策划/剧本/分镜/美术成品/音频/测试由人完成；AI 主要用于**程序实现**与**少量美术底图辅助**。

## 1. 是否使用 AI · 用了什么

| 用途 | 工具 | 说明 |
|---|---|---|
| **程序实现** | AI 编程助手（大语言模型，运行于 Godot 4.7 / C# 环境） | 生成代码初稿、重构、修 bug、整理文档 |
| **美术（辅助）** | Stable Diffusion | 仅辅助**少数定景底图 / 石材材质**；成品由人手绘、修图、抠像、统一风格 |
| **音频** | 无 | 全程**人工**录制 / 混音 |
| **策划 / 剧本 / 分镜 / 需求** | 无 | 人工 |
| **测试 / 验收** | 无（AI 仅按反馈修） | 人工测出问题、人工复核 |

## 2. 规模与用量

| 项 | 总量 | AI 参与比例 |
|---|---|---|
| 程序代码 | 约 **7,860 行 C#**（42 个文件 / 三个模块） | **约 90%** 由 AI 生成初稿 |
| 美术资产 | **84 张** | **约 5–10%**（少量定景底图/材质的 SD 辅助） |
| 音频 | **约 40 条** | **0%**（人工） |
| 策划/剧本/分镜/需求文档 | 数万字 | **0%**（人工） |

## 3. 各部分 AI 参与度（谁做了什么）

| 部分 | AI | 人工 |
|---|---|---|
| 程序（~7,860 行） | 生成代码初稿、重构、修 bug、写脚手架 | **需求定义、架构取舍、审阅修改、联调、验收、演示** |
| 美术（84 张） | 个别底图/材质的 SD 辅助 | **人绘 / 修图 / 抠像 / 统一风格 / 把关** |
| 音频（~40 条） | — | **人工录制 / 剪辑 / 归一化口径** |
| 策划·剧本·分镜（数万字） | — | **人工原创** |
| 测试 | 按反馈修复 | **人工测出 65 条问题 + 逐项复核** |

## 4. 人工工作量（这才是主体）

- **叙事与设计**：完整剧本 + 分镜稿 + 四份需求文档（美术/音频/玩法/工程），数万字。
- **美术**：84 张资产（俯视地图、人物、道具、UI、封面……）人绘为主，SD 仅点状辅助。
- **音频**：38 条音效/环境音/主题曲，人工制作。
- **质量**：**65 条人工 bug 反馈**逐条复现、修复、复核；7 个结局全流程人工试玩验收。
- **方向与取舍**：玩法裁剪、节奏、结局结构、RPG 探索口径的拍板均由人。

## 5. 口径与承诺

- **AI 占比高的只有"程序代码"**（实现层面）；**玩法、叙事、美术、音频、验收判断 100% 是人**。
- 所有 AI 产出（代码/文档）都**经人审阅、运行验证、测试回归后**才入库；测试不通过不合并。
- 美术用 SD 的部分**均经人手选/修/重绘**，非直接使用。
- 源码与文档全在仓库内，AI 参与的部分**可追溯、可复现**（提交历史 + 反馈台账）。

# 这是美术岗生成的 墓时（Mobius Meovverse）AI 使用说明

一、是否使用 AI
使用了。分三类：AI 编程助手、AI 图像生成、AI 文本辅助。音频与人工作画未使用 AI 生成。

二、用了什么 AI、规模、使用量
1. AI 编程助手（主力，用于程序实现与工具脚本）
   规模：C# 代码约 5,700 行 / 33 个文件；配套 Python 工具链约 8,000 行 / 44 个脚本（像素化、调色板吸附、地图与立绘管线、测试钩子）。
   使用量：开发期持续使用，按任务分批推进；完成 3 名成员协作的 56 次提交、12 章 + 序章 + 尾声 + 4 个结局的全部流程可玩。
2. AI 图像生成：本地部署 Stable Diffusion（ComfyUI 工作流，含 img2img、inpaint、批量变体）
   使用量：累计出图 240 张以上（中间产物全部留档在 raw/），筛选、修正后入库纹理 100 张。
3. AI 文本辅助：仅用于文档校对、检索与条理整理，不生成剧情内容。

三、哪些部分使用了 AI
- 程序代码：AI 起草为主，人工定架构与验收。
- 场景、道具、封面底图：Stable Diffusion 出底图，再走自研脚本转为硬像素资产。
- 角色、立绘、小人、UI 边框：人工绘制为主，SD 少量辅助。
- 音频 30 件：全部人工制作与整理，0% AI。
- 终章过场动画：人工画 4 张关键帧，脚本确定性合成；未使用图生视频。
- 剧本、分镜、技术方案：策划与程序人工主笔。

四、AI 占比（估算）
代码：AI 起草约 85%，人工原创约 15%（架构、接口契约、核心抽象、验收钩子）；此外代码审查、调试、问题定位与全部测试由人工完成。
美术：AI 参与约五成。场景/道具类 AI 占比高，角色与人物类以人工为主；AI 出图一律经人工筛选、手修与像素化验收后才入库。
音频：0%。
文案与策划：AI 辅助约两成，内容与判断均由人工给出。
全项目综合：AI 参与约六成，集中在代码实现与底图生成。

五、人工有效工作量
- 文档 18 份、约 4,200 行，含剧本、分镜稿、技术方案、美术与音频需求，全部由人工撰写与维护。
- 定义 82 个资产槽位与 12 张 Plate 的资源规范、六动词玩法契约与验收标准。
- 建设 50 项以上集成测试与自动对账，用于 AI 产出的回归验收。
- 人工完成角色美术、AI 底图筛选与手修、全部音频制作，以及 AI 代码的审查、调试与集成。
- 每一条 AI 产出都经人工判断、集成、测试后才进入版本；生成脚本与中间产物全程留档（raw/、tools/），可追溯、可复核。

六、结论
AI 在本项目中是执行工具，不是创作主体。剧本、分镜、玩法设计与验收标准来自人；AI 承担重复性实现与出图；方向判断、审美定稿与质量把关由人负责。使用透明、可控、可追溯。
