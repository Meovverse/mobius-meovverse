## 0. 四条铁律（违反即返工）

### 铁律 1 · 不画微观质感

游戏的全部质感来自**程序化 shader**（刀口毛边、石粉堆积、纸纤维、水泥砂粒）。
美术交付的位图里**只有大形与块面**，没有一根一根的刀痕。

| 谁负责 | 负责什么 |
|---|---|
| **美术** | 字形轮廓、石材块面明暗、纸的底色、人的轮廓与姿态 |
| **程序（shader）** | 刀口毛边、石粉颗粒、纤维走向、砂粒、墨色深浅 |

> 这条是本项目的**省钱核心**。如果美术去画刀口毛边，一张碑要画 6 小时，而且改一个数值就得重画。
> 交给 shader 之后，一张碑的美术成本是 **1.5 小时**。

### 铁律 2 · 三阶明暗，不许渐变

每个物件最多 **3 阶明暗 + 1 阶高光**，且相邻明暗之间必须是**硬边**。
参考：暴雪《黑角》/《炉石》的 3 阶石头。

- ✅ `#3a3a3a → #555555 → #707070` 三块硬边
- ❌ 从 `#3a3a3a` 到 `#707070` 的 8 级过渡

### 铁律 3 · 一个物件一张图，一张图一套光照

- 每个 PNG 只画**一种光源**（统一来自**左上 45°**）。
- 不要在一张图里画两种光源，不要画投影（投影由 shader 加）。

### 铁律 4 · SD 能做什么、不能做什么 ★（v3 新增）

美术主要用 Stable Diffusion 出图。**SD 的强项和这个项目的需求正好错位一半**，所以下面这张表是硬边界，不是建议。

| 需求 | SD 能做？ | 原因 / 替代方案 |
|---|---|---|
| 场景背景的大形与气氛 | ✅ 能 | 正好是 SD 强项 |
| 角色、道具的轮廓与姿态 | ✅ 能 | 同上 |
| 材质块面（三阶明暗） | ⚠ 勉强 | 必须靠负向提示词 + 后期量化，硬扛会出渐变 |
| **任何汉字** | ❌ **绝对不行** | SD 会画出一堆似字非字的乱码。**所有文字由程序用字体叠加**——这反而是好事，因为 `mask` 需要精确字形 |
| **通道分离的遮罩/数据图**（`mask_*`、`map_*`） | ❌ 不行 | SD 不理解"这张图是给 R 通道用的"。**必须用字体排版 + 脚本分离** |
| **无缝平铺噪声**（`noise_*`） | ❌ 不行 | SD 的纹理没有周期性，边缘必然对不上。**必须程序生成** |
| **同一把刀口在两张图上一致** | ❌ 不行 | 这正是 `A2 + B2 + E3` 必须同源的要求。**SD 每次都会给出不同的刀口** → 这三张必须手绘或脚本生成 |
| 精确尺寸 / 精确坐标 | ❌ 不行 | 交给 `tools/pixelart.py` 缩放 |
| 印章（带弧形汉字） | ❌ 不行 | **程序用字体绕排 + 几何图形画** |
| 无半透明、无抗锯齿 | ❌ 不行 | SD 一定会给。**工具链强制二值化** |

**结论：SD 负责"形状和气氛"，程序负责"像素、通道、文字、周期"。**
这两件事不要混在一起做——SD 出完就不要再让 SD 碰那张图了，
像素化、通道分离、调色板吸附全部交给 `tools/pixelart.py`。

## 1. 全局规范

### 1.1 命名

```
前缀_主题_序号[_变体].png

bg_    场景背景（全屏）
char_  角色
prop_  道具
doc_   文件/纸张
ui_    UI 元件
fx_    特效贴图
mask_  遮罩（决定形状与判定区域）
map_   数据图（编码批次/材质 ID）
noise_ 噪声（供 shader 平铺）
```

- 全部**小写 + 下划线**，不得出现中文、空格、大写。
- 例：`stele_A7_face_base.png`、`mask_stone_glyphs.png`、`noise_stone_grain_64.png`

### 1.2 尺寸与格式

| 项 | 规定 |
|---|---|
| 原生分辨率 | **640 × 360**（全屏）或按 §2 总表逐项指定 |
| 缩放 | 允许整数倍缩放（2× / 3× / 4× / 8× / 12×），**禁止非整数缩放** |
| 格式 | PNG，8-bit，**RGBA**（带 alpha 的物件）或 RGB（背景） |
| 抗锯齿 | **禁用**。所有边缘必须是硬像素台阶 |
| 半透明 | **禁止使用半透明像素**。需要透的地方用 alpha 通道（0 或 255） |
| 淡出效果 | 用**不透明的浅色**，不要用半透明白 |
| 导入设置 | Filter = Off（Nearest）、Mipmaps = Off、Repeat = 视用途（见 1.4） |
| 切图 | **不要切图集**，不要拼大图。一物件一文件 |
| 半透明白名单 | 只有 `G2 ui_loupe_glass_96.png`（镜片径向暗角，是光学现象） |

**颜色数上限**（按类别，`check` 会自动判定）：

| 类别 | 上限 | 说明 |
|---|---|---|
| `bg` 全屏背景 | **16** | 背景需要更多灰阶才不会糊成一片 |
| `prop` 道具 | **10** | |
| `char` 角色 | **10** | |
| `ui` UI 元件 | **8** | |
| `fx` 特效 | **6** | |
| `noise` / `mask` | 不限 | 前者要灰度连续，后者只用 0/255 |

> ★ 上表与 `tools/pixelart.py` 里的 `MAX_COLORS` 是同一份规则。
> 改了一边必须改另一边（脚本里改 `MAX_COLORS`）。

### 1.4 通用元数据

- **锚点**：角色 / 道具的**底部中心**为 `(0.5, 1.0)`，坐标写在 `.import` 的备注里交给程序。
- **朝向**：默认面朝**左**。需要面朝右的另出一张后缀 `_r`。
- **留白**：物件四周留 **≥ 2px** 透明边，防止采样时切到邻边。
- **重复（平铺）**：`noise_` 开头的一律**必须无缝平铺**，Repeat = Enable。

## 1.5 SD 工作流（v3）

### 1.5.1 管线

```
①  SD 出高分辨率草图（1024×576，16:9）        raw/bg_graveyard_area_A.png
     ↓  多出 3–5 张挑一张
②  去噪 → 像素化 → 调色板吸附 → alpha 二值化      tools/pixelart.py convert
     ↓
③  程序叠加文字（汉字、印章弧形字、表格字段）      程序
     ↓
④  机器验收                                       tools/pixelart.py check --strict
     ↓
⑤  人工精修（只改坐标和结构，不再改明暗）         Aseprite / Photoshop
     ↓
     assets/textures/bg_graveyard_area_A.png
```

**关键纪律：第 ② 步之后不要再回到 SD 重画。** 一张图只在 SD 里存在一次，
重画会让它的风格和已经定稿的其它图对不上。

### 1.5.2 模型与参数

| 项 | 建议 | 理由 |
|---|---|---|
| 底模 | **SDXL**（或 SD 1.5 也可以，但要出到 512×288 再放大） | 16:9 原生 1024×576，比 SD1.5 的 512 干净 |
| LoRA | 像素画 LoRA，**权重 0.55–0.7** | 权重超过 0.8 会把细节烧成噪点；低于 0.5 会出不来硬边 |
| 尺寸 | **1024 × 576**（= 目标 640×360 的 1.6 倍） | 留出降采样的余量，又不至于让像素感糊掉 |
| 采样器 | **DPM++ 2M Karras** | 稳定，不出油画笔触 |
| Steps | 28–35 | |
| **CFG** | **5–6**（重要） | ★ 这个项目要"平"，CFG 一高就会出假细节和渐变。**不要超过 7** |
| 批量 | 每张 **4–6 张**，seed 固定后再微调 | 固定 seed 是让 C1 和 C2 看起来像同一个墓地的前提 |
| img2img 细化 | denoise **0.35–0.5** | 只用来收结构，不要用来换内容 |

### 1.5.3 通用负向提示词（所有图共用）

```
pixel-art, lowres, blurry, jpeg artifacts, antialiasing, gradient,
smooth shading, soft shading, airbrush, 3d render, octane render, photorealistic,
text, letters, chinese characters, numbers, watermark, signature, logo,
colorful, oversaturated, neon, purple, lens flare, bokeh, depth of field,
glow, bloom, drop shadow, rim light, vignette,
dithering, noise, grain, multiple people, cropped, out of frame, deformed
```

> ★ `colorful` / `oversaturated` / `purple` 这三条别删。
> 这个游戏是**灰的**，全篇只有印泥和苏老师的外套有颜色。
> SD 一旦放飞就会给你一片蓝天绿地，那是这个项目最常见的失败模式。

### 1.5.4 为什么要 `--smooth 2`（量化之前的去噪）

SD 的输出永远带高频噪点。直接吸附到 N 阶调色板时，噪点会跨过色阶边界，
在每条色阶的分界线上炸出一片**抖动点（dithering）**——而负向提示词里明确禁止 dithering。

`--smooth 2` 在量化前做一次半径 2 的盒式模糊，色阶边界就干净了。

| radius | 效果 |
|---|---|
| 0 | 抖动点明显，不可用 |
| **2** | ★ **SD 图一律用这个** |
| 3 | 更干净，但会开始吃掉 1px 的结构 |

⚠ **已经是像素美术的图绝对不要加 `--smooth`**（会糊掉硬边）。
`--smooth` 只用于 SD 原始输出。

### 1.5.5 三条易错的地方

1. **SD 喜欢"电影感"**——大景深、体积光、雾气。这些全部要负向掉。
   这个游戏的美术是**平**的：阴天、无雾、无投影。
2. **SD 喜欢"多"**——多棵树、多个人、多细节。要在正向下明确写 `empty`, `sparse`, `few details`。
3. **SD 出图带 2:3 或 3:2 的比例**。生成后**先裁到 16:9 再进管线**，
   不要指望管线帮你裁（裁会切掉主体）。

### 1.5.6 工具

`tools/pixelart.py`（本仓库自带，已跑通）：

```bash
# 导出调色板给 Aseprite / Photoshop 用
python3 tools/pixelart.py palette stone

# 场景背景：SD 的 1024×576 → 640×360 硬像素，12 阶灰
python3 tools/pixelart.py convert raw/bg_graveyard_area_A.png \
    --out assets/textures/bg_graveyard_area_A.png \
    --size 640x360 --resize --smooth 2 --palette levels:12

# 道具：裁到主体、等比放进画布、吸附调色板、alpha 二值化
python3 tools/pixelart.py convert raw/prop_toolbox.png \
    --out assets/textures/prop_toolbox.png \
    --size 160x100 --trim --smooth 2 --palette stone --binarize-alpha

# 噪声图无缝化（程序生成的也要过一遍保险）
python3 tools/pixelart.py tile assets/textures/noise_chisel_a_32.png

# 验收：尺寸 / 半透明 / 颜色数 / mask 纯度 / 噪声接缝
python3 tools/pixelart.py check assets/textures/ --strict
```

详见 `tools/README.md`。

## 3. 逐张详细说明

### A · 噪声贴图（P0，最先做）

这 6 张是**整个项目的地基**，程序 shader 靠它们出质感。**先做完这组，项目才有可能跑起来。**

#### A1 `noise_stone_grain_64.png` · 64×64 · RGB · 无缝平铺
- 山西黑的**颗粒感**。黑白灰，不要偏色。
- 结构：低频斑块（8–16px 尺度的深浅块）+ 高频颗粒（1px 的碎点）。
- 颗粒要**硬**（单像素），不要糊。
- 参考：花岗岩近摄，或《凯瑟琳》的石材。

#### A2 / A3 `noise_chisel_a_32.png` · `noise_chisel_b_32.png` · 32×32 · RGB · 无缝平铺
> ★★ **全项目最重要的两张图。**"靠质感分辨新旧"这个核心玩法全靠它，
> 而且**玩家唯一的参照物是 `E3 prop_scrap_stone.png` 料头上同一套刀口**。
>
> **它俩的差别必须"一眼能看出不同，但说不出哪里不同"。**
> 这个要求在 v2 里变得更严格了：玩家会先在料头上看 30 秒"对的刀口长什么样"，
> 然后带着这个记忆回碑上比对。**如果 A 和 B 的差别需要解释才能发现，第一章就废了。**

| | `noise_chisel_a`（批次 A = 陆昀 2021 年刻） | `noise_chisel_b`（批次 B = 补刻） |
|---|---|---|
| 条纹方向 | 顺着走刀方向，**长而连续**（至少连 8px 不间断） | 同样方向，但**断裂、长度只有 A 的 1/3** |
| 边缘 | 平滑，有 1px 的**翻起毛边**（一侧亮一侧暗） | 边缘毛躁，毛边成簇，**有崩口**（1–2px 的黑缺口） |
| 亮度 | 均匀 | 有深浅不匀（"手劲没控制好"） |
| 密度 | 中等（约 60% 覆盖） | **密**（约 85% 覆盖，新錾子下手重） |
| 翻起毛边方向 | 全部朝**同一个方向**（右） | **两个方向都有**（改碑的人握姿不同） |

**最后一行（毛边方向）是 v2 新增的关键**：光是"乱"和"整齐"玩家可能归因于"手生手熟"，
但**毛边朝向不一致**是"这不是同一个人同一把錾子刻的"的硬证据。
→ `E3 prop_scrap_stone` 上的刀口必须与 `A2` 完全同源（毛边都朝右）。

**具体做法**：先用 #808080 中灰铺满，然后沿**水平方向**画条纹（条纹会随笔画的旋转被 shader 旋转），
最后叠 1px 硬噪声。A 用长条，B 用短条 + 更多崩口 + 反向毛边。
**记得无缝平铺**：左右边缘要能接上，最省事的做法是画完复制右半边到左半边、再复制下半边到上半边。

#### A4 `noise_paper_fiber_64.png` · 64×64 · RGB · 无缝平铺
- 纸的**纤维走向**，明显是**横向拉丝**。
- 拉丝是硬的、稀疏的（约每 6–10px 一根），不是连续纹理。
- 第三章"叠纸看折痕"和"看纸纤维"要靠它。

#### A5 `noise_dust_32.png` · 32×32 · RGB(A) · 无缝平铺
- 白色细石粉。**必须很细**（1px 为主，少量 2px 团）。
- 用在"擦"的覆盖层，也是"石粉堆积 Pile"的表现源。

#### A6 `noise_cement_64.png` · 64×64 · RGB · 无缝平铺
- 水泥：砂粒感 + 少量小气孔（2px 黑点）。
- 用于终章 90 秒扒水泥演出。

### B · 石碑（P0）

#### B1 `stele_A7_face_base.png` · 640×360 · RGB · **无 alpha**
**碑面石材底图（不含字）。**
- 一整块黑灰的石材，占满画面。画面比例约 **碑面 5 : 3**（碑比屏幕高，让玩家感到"这么大一块石头"）。
- 主体是 3 阶明暗（`#1a1a1a` 底 / `#3a3a3a` 中 / `#6e6e6e` 光），边缘留一圈更暗的框（碑的倒角）。

- 全图要能看出**轻微的水平层理**（石材沉积纹），暗示这是山西黑。
- **不要写字。**

#### B2 `mask_stone_glyphs.png` · 640×360 · **RGBA** · 无 alpha 混合
> ★ **这张图同时是美术资产和游戏的判定数据。程序从这张图算距离场来判"描"得对不对。请务必按下面的通道约定交付。**
> **v2 更新**：新增「湘」残迹要求（R 通道）、新增「十」字距要求（A 通道）。

碑上刻的是：
> **韩梅，女，一九八五年生，二〇二一年五月十六日卒。**

分区如下（**必须严格按通道分**）：

| 通道 | 内容 | 说明 |
|---|---|---|
| **R** | 「韩」+「梅」的**木字旁** + 句读「，」+ ★**「湘」被磨除后的残迹** | 旧刻（Batch A），正常的部分 |
| **G** | 「梅」右半的「每」，**排除**可疑的那一横 | 旧刻（Batch A） |
| **B** | 「每」的最下面**那一长横** ← 全篇要找的那一笔 | **补刻（Batch B）** |
| **A** | 姓名以外的**整行正文**（女，一九八五年生…卒。）+ ★**「六」底下「七」的残迹** | 正常刻字区域 |

##### ★ v2 新增要求 1：「七」的残迹（A 通道）

「六」被磨掉重刻了。程序需要玩家**擦开石粉后描出底下「七」的轮廓**，所以：

- 在「六」的正下方（不是旁边，是**叠在「六」的位置上**）画出「七」的完整字形。
- 强度：**比正常的字口浅 40%**，边缘破碎，像被砂纸蹭掉了一半。
- 但**形状必须完整可辨**——玩家要能描出它的轮廓。
- 描出轮廓之后，`A` 通道的透明度会由程序降到 30%，露出 `B1` 底下那层"七"的实际字形。

##### ★ v2 新增要求 2：「十」字往左挪了 2mm（这是段三的第一级台阶）

> 原文：「改碑的人为了塞进去，把『十』往左挪了两毫米」

**这是玩家在擦之前、不用擦、抬头就能看见的唯一线索。**所以它必须画得出来：

- 正文行里，「十」与左右两字的间距：行内其他字距是 **28px**，
  「十」左边（与「五」）的间距必须是 **26px**，右边（与「六」）是 **28px**。
- → 视觉上「十」往「五」那边挤了 2px。
- **2px 在 640×360 下只有 1 个像素台阶**，请务必确认你在 4× 预览下能看出这个台阶。
- ★ 这一条在 `B2` 和 `B1` 里都要做（`B1` 上是看不见字的底图，所以实际只有 `B2` 生效；
  但 `B4 stele_A7_full` 上也要有同样的字距，远景才可信）。

##### 字形规范

- **宋体**（剧情：招牌和碑都用宋体，他嫌楷体太软）。
- **字口宽 2mm** → 在图上表现为**刻痕宽度 6–7px**，笔画末端有直角收笔。
- 「梅」的字面高度 **约 130px**（放大 12 倍像素字）。
- 正文行**从左到右**排，字间距 **28px**（故意松，像碑）。
- 「韩」和「梅」之间留 **20px 空隙**——因为这里原本刻的是两个字（韩湘）。

> ⚠ **交付注意**：`B2` 的字形请**先用 12px 像素字体排版，再整数放大 12 倍**描成硬像素，
> 这样宋体的骨架能拿到，但边缘是硬台阶。**不要**直接用矢量字体平滑缩小。

**美术另外需要交付一份文字说明文件 `stele_A7_glyphs.md`**（不是图），
列出每个通道包含的笔画数、各字形的**包围盒坐标**，以及：
- 「六」底下「七」残迹的包围盒
- 「每」那一横的包围盒
- 「湘」残迹的包围盒

程序会用这张表 + 通道范围来生成判定折线和段三的字距判定。

## 5. 需要美术特别注意的四个坑

### 坑 1 · 「梅」字下面那个「湘」怎么办
这是全篇最重要的一个视觉谜题。处理方式：
- 在 `B1`（碑面底图）上，**在姓名正下方**画一块**形状不规则的磨痕区域**。
- 这块区域用 `#6e6e6e`（亮）为主 + 少量 `#1a1a1a`（残存笔画），**像被砂纸磨过**。
- ★ **不要在这块区域画出「湘」的字形**——只画**看得出"这里原来是字"但认不出是什么**的残迹。
- ★ 「湘」字的**碎笔轮廓**画在 `B2` 的 R 通道（判定用），对应 `B3` 的 Batch C（渲染用）。
- 玩家要在放大镜下看清它的碎笔轮廓，然后才能**描**出它的形状。

### 坑 2 · 场景图不要画太满
`bg_*` 的作用是**托住主体**，不是抢戏。
- 细节集中在画面**四周**，中央 60% 区域保持简洁、低对比。
- ★ 所有 `bg_*` 都不要在画面里画人（人物用 `char_*` 单独放，方便做动画和换装）。
  → 这也是 SD 特别容易犯的错：**别让它在背景里生成人群**，除了 `C2` 明确要求的那一群。
- ★ `bg_*` 的**明暗对比要比主体低一档**。主体（碑/纸/账本）才是最黑的那块。
- ★ SD 出完 `C1` 之后，`C2` 请用 `C1` 做 img2img（denoise 0.4），
  这样两章的墓地**看起来是同一个地方**，这是叙事连贯性的一部分。

### 坑 3 · 像素对齐
- 所有非整数位置的物件，坐标**取整**到像素。
- 程序会做屏幕空间的整数放大，所以如果美术在 640×360 里画了半个像素的偏移，放大后会看到抖动。
- 建议美术**开一个 640×360 的画布，缩放预览设为 3× 或 4×**再画。
- ★ 走 SD 管线的话，这一条由 `tools/pixelart.py` 的降采样保证，
  **不要在 SD 出图后手动再缩放**，会引入非整数缩放。

### 坑 4 · 透明边缘不要半透明
- 半透明像素在最近邻放大下会变成**一列脏边**。
- 淡出的效果请用**不透明的浅色**（纸变淡就画浅色，不要画半透明白）。
- ★ SD 一定会输出半透明边缘，**必须过 `--binarize-alpha`**，不要手动抠。

### A.4 明确**不要**写进提示词的东西

| 不要写 | 为什么 |
|---|---|
| `chinese characters` / `text` / `signs` | SD 会画乱码，还会把版面搞脏 |
| `sunset` / `golden hour` / `warm light` | 这个游戏的光是**阴天的天光**。暖调一进来就毁了 |
| `blue sky` / `green grass` | 草地是**枯黄**的（`#b9ad91` 一类），天空是灰白的 |
| `fog` / `mist` / `atmospheric haze` | 不要大气透视。这个游戏是**平的** |
| `detailed` / `intricate` / `highly detailed` | 反向的 SD bias，会烧成噪点 |
| `realistic` / `photorealistic` | 会出抗锯齿和渐变，管线要跟它打架 |
| `sun` / `shadow cast` | 统一左上 45° 单光源，投影交给 shader |
| `vignette` | 负向里有；要暗角的话程序用 shader 加 |
