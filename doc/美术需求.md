## 2. 程序已经接管了什么（不用你管，但你要知道）

启动时会打印这张对账表（`SlotRegistry.Audit()`）：

```
════ 资产槽位对账 ════
  槽位总数     41
  美术要做     7   ← 这就是全部了
  程序生成     26
  代码绘制/叠字 8（不占贴图槽）
```

| 原需求表里的 | 现在的归属 | 为什么程序做得更好 |
|---|---|---|
| `mask_stone_glyphs`（碑面字形遮罩） | ★ **程序从字体烘焙** | 它同时是**游戏的判定数据**。玩家的"描得对不对"由它算出。如果它来自美术，构图一旦和我们的假设不符，判定就废了 |
| `map_stone_carve`（批次 ID 图） | 程序从遮罩推导 | 同上 |
| `noise_*` 六张 | 程序生成 | 用**周期函数**构造，天然无缝。手画做不到保证 |
| `noise_chisel_a/b`（刀口纹理） | 程序生成 | ★ 差别做在**毛边朝向**上：A 全部朝右、B 双向 + 崩口 + 密度更高。这是"不是同一个人同一把錾子"的硬证据，程序算得比画得准 |
| `prop_scrap_stone`（练手料头） | 程序生成 | ★ 它和碑面**共用同一套刀口**，所以"同一个人刻的"是算出来的，不是画出来的 |
| `stamp_*` 四张印章 | 程序生成 + 字体绕排 | 中文印章手画/S D 都会出乱码。程序用字体绕排，弧形文字是准的 |
| `ink_signature_suhang` | 程序字体渲染 + 形变 | 签名要"工整到有点假"，程序加形变正好 |
| `fx_crease_set`（折痕） | 程序生成 | ★ 中段那个 1px 错位是"同源"的唯一特征，必须精确 |
| `ui_*`（放大镜环、卡尺、手形光标） | 程序用 Draw API 画 | 卡尺刻度要对齐像素格、放大镜环要正圆。程序画出来天然干净 |
| 纸页、纸纤维、粒子、结局卡底 | 程序生成 | |
| 全部道具（账本封面、台账、登记表、工具箱） | 程序生成 | 台账上"压得更深的那一行"是玩法，程序能保证它在 |

## 3. ★ 复用原则（v7 新增，剧本还在改）

### 3.0 每张图标了「复用面」

| 标记 | 含义 | 该什么时候做 |
|---|---|---|
| 🟢 **完全复用** | 剧本怎么改都不会作废 | **现在做** |
| 🟡 **半复用** | 主体不变，文件名或触发点可能要改 | 现在做，改名成本低 |
| 🔴 **剧本绑定** | 剧本定稿前不要做 | 等通知 |

**你要做的 7 张里，5 张是 🔴**——但这不影响开工，因为：
即使剧本整个推翻重写，下面这些资产一个都不会白做：

```
🟢 完全复用（≈2 小时，建议先做掉）
  ui_loupe_ring        放大镜环       六个动词之一，剧本改不到
  ui_caliper           卡尺           同上
  ui_cursor_hand       手形光标       同上
  ui_dialog_frame      对话框         任何有对话的场景都要（已交付）
  prop_scrap_stone     练手料头       ★ 第一章的核心道具，判定数据
  stamp_* ×4           印章           第三章要对比的物证
  fx_crease_set        折痕           第三章叠纸的判据
```

**先把这批做掉，剧本随便改。** 反正程序生成的版本已经在跑了，
你做的是"更好看的那一层"。

### 3.0.1 ⚠️ 最容易白做的一件事

**背景不要用 img2img 串起来。**

比如「墓园 A 区」和「清明落成仪式」这两张——
它们现在看起来像"同一个墓地的两个时刻"，程序建议用 img2img 串，
但**如果剧本把清明那场删了，第二张就白做了**。

所以：**两张分别独立出图。** 视觉上的连贯性由
「同样的调色板 + 同样的地平线高度 + 同样的光源方向」保证，
不靠 img2img。SD 用同一个 seed + 同一段负向词就能做到。

> 上一版（v6）我在提示词里写了"用 A2 做 img2img 做 A3"——
> **这条撤回。** 绑死两张图的风险不值得。

### 3.0.2 人物的复用面最差

人物改名（已经发生过两次）、改年龄、改服装都会让图作废。所以人物**放在最后**。

换版后的处理：
- `char_suteacher_portrait`（苏老师）→ **苏老师这个角色不存在了，改作韩梅的档案照**。
  档案照本来就该是证件照质感，这张正脸肖像正好对得上，**基本不用改**。
- `char_laofan`（老樊）→ **老樊也不存在了**，改作墓园经办 / 殡仪馆窗口。

> ★ 这两张能这样"平移"，是因为它们本来就是**人像**，而新剧本里仍然需要人像
> （韩梅的档案照）+ 功能角色（窗口的人）。**如果不是这样，这两张就白做了。**

### 3.0.3 老吴（主角）的图还没交，而且换版后要的是**老年版**

`char_luyun_back` 这一槽位从四十多岁改成了**六十多岁**（2026 年的老吴）。
终章蹲着扒水泥那 90 秒是全篇情绪最高点，需要他的背影，而**没有它那一段演不了**。

**老年版怎么画**：肩线塌一点、背更弯、手上的动作慢一点、头发花白。
不用改画幅，改的是姿态和气质。

> ⚠ 这张是 🔴 剧本绑定（主角可能再改描写），但**它不能不做**。
> 建议做一版**可复用的**：背影不露脸，所以"四十多岁"和"六十多岁"可以出成
> 同一张图的两个版本（`char_luyun_back` / `char_luyun_back_old`），
> 序章用年轻的、终章用老的。这样万一剧本再改也不用重画。

## 4. ★ 美术方向调整（v6）

### 4.1 「全篇不画正脸」这条规则改了

原规则的理由是**省钱**：不给表情就不会画崩，是一个成本决策。
现在苏老师有一张真正好的正脸肖像，而**她是全篇的情感支点**（第四章那一句
「小伙子，这是谁的碑」）。

所以规则改成一条**叙事规则**，而不是成本规则：

> **苏老师是全篇唯一一个正面朝向玩家的角色。**
> 老吴、苏航、墓园经办一律背影或剪影——因为玩家在意的从来不是人，是石头。
> **她停下来转过身来看你，这就是这个游戏里唯一一次人的脸出现。**

这比原来的成本规则更强，而且现在有图能撑住它。

### 4.2 颜色规则放宽

实测：苏老师量化到 12 级之后**颜色被保留了**（逐通道量化的副作用），
蓝衣棕围巾都还在，画面读起来是"刻意的低饱和色块"而不是脏。

于是规则改成：

> **画面整体接近灰，但允许人物保留少量低饱和本色。**
> 调色板的朱红只用在印章和标语；深蓝只给苏老师。
> **她是全篇色彩最重的人**——这和 §3.1 是同一件事的两面。

### 4.3 交图要求（比 v1 松很多）

#### 4.3.1 硬性要求只有一条：**尺寸**

程序会把你的图**自动缩放到正确尺寸**（像素图用最近邻），所以尺寸不对不会毁图，
但缩放越多越糊。**请直接按表里的尺寸出。**

#### 4.3.2 其他都会被自动修正

| 你的图可能这样 | 程序会怎么处理 |
|---|---|
| 颜色超过上限 | 自动量化到调色板 |
| 边缘半透明 | 自动二值化 |
| 带渐变、柔边、抗锯齿 | 量化时会被压成硬边 |
| 名字不完全一致 | 认不出来的槽位**直接用程序版**，不会报错也不会卡 |

> ★ 所以：**你不需要读 v1 那些"三阶明暗 / 无抗锯齿 / 无半透明"的规矩。**
> 已交付的 8 张里，苏老师那 28365 色、老樊 46 色，都是程序自动收掉的。
> 那是给手工作业定的，交给程序兜底了。
> 你只需要保证**画面的内容和气氛对**。

### 4.4 唯一要守的美术约束

- **640×360 是原生分辨率**，整张图按这个比例画。
- **整体接近灰，但人物可以保留少量低饱和本色**（见 §4.2）。
  场景和道具一律灰阶；人物可以有本色 —— 苏老师的蓝衣就是这么来的。
  纯色只有两个：印泥的朱红 `#a8352c`（只用在印章和标语）和苏老师的深蓝 `#3a4450`。
  不要蓝天、不要绿草（草地是**枯黄**的）、不要金色夕阳。
- **光源统一左上 45°**。不要在一张图里画两种光源。
- **背景图里不要画人**。人物是单独的槽位，要能做动画。
  （A3 清明那张**例外**，那一张的人群就要画进去。）
- **文字不要画进图里**。程序会叠字，你画了会和程序的重叠。

### 4.5 交付方式

直接放进 `res://assets/textures/`，文件名用上表的。
程序下次启动会自动接管并打印它改了什么（按 **F3**）。

## 5. SD 出图参数（如果你用 Stable Diffusion）

### 5.1 参数

| 项 | 值 |
|---|---|
| 尺寸 | **1024 × 576**（= 640×360 的 1.6 倍，留降采样余量） |
| 采样器 | DPM++ 2M Karras |
| Steps | 28–35 |
| **CFG** | **5–6**（★ 高了会出假细节和渐变，程序量化会跟它打架） |
| LoRA | 像素画 LoRA **0.55–0.7**（超过 0.8 会烧成噪点） |
| 批量 | 每张 4–6 张，固定 seed 后微调 |

**通用负向提示词**（所有图共用）：

```
pixel-art, lowres, blurry, jpeg artifacts, antialiasing, gradient,
smooth shading, soft shading, airbrush, 3d render, photorealistic,
text, letters, chinese characters, numbers, watermark, signature, logo,
colorful, oversaturated, neon, blue sky, purple, sunset, golden hour,
warm light, lens flare, bokeh, depth of field, fog, mist,
glow, bloom, drop shadow, rim light, detailed, intricate,
crowd of people, cropped, out of frame, deformed
```

> ★ `colorful` / `blue sky` / `sunset` / `fog` 这几条别删。
> SD 一放飞就给一片蓝天绿地加体积光，那是这个项目最常见的失败模式。

## 6. 不做会怎样

**不会怎样。**

程序版全部能跑，只是难看：
- 背景 → 三阶色带 + 剪影。第一章照样能玩，判定完全不受影响。
- 角色 → 剪影 + 边光。姿势是对的（程序生成的剪影按蓝本画的）。
- 碑全景 → 程序版是平面图，第一章开场会少一点体积感。

**唯一真正受影响的是 A2 和 A7**：一个是全场的空旷感，一个是第四章的情绪支点。
这两张值得花时间，其余五张随缘。

**整张不能当"背景主体"（定景口径下），但已在最大程度复用。** 定景墓园背景仍是三层：
