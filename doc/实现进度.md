## 三、三条架构决定（别推翻它们）

### 1. ★ 判定数据 100% 程序生成，绝不读美术图

`SteleBuilder` 用字体现场烘出字形遮罩 → 得到 `Height` / `BatchMap` / `CarveMark` 判定区。
**美术的 `mask_stone_glyphs.png` 一律不读**（需求表里那张图作废，或者只当装饰）。

理由：美术资产会晚到、尺寸会不对、构图会和我们的假设不一致。
而"玩家描得对不对"这件事不能依赖别人的构图。

**代价**：需要一张程序生成的 `data/gen/stele_glyphs.png` 落进仓库。
它不是美术资产，任何人跑 `BakeGlyphs` 都能重新生成；丢了游戏会自动退回运行时烘焙。

### 2. ★ 美术资产是覆盖层，不是前置依赖

`AssetIntake` 接管每一张贴图：

```
美术的图 → 尺寸纠正 → 半透明二值化 → 颜色量化 → 噪声图强制无缝 → 调色板
没交    → ProcGen 程序生成
都没有  → 纯色兜底，永不返回 null
```

每一次被迫的修正都记进 `AssetIntake.Report`，按 **F3** 打印。这样美术能直接看到程序改了什么。

### 5. 六个动词共用一份 `SurfaceModel`

`Height` / `Dust` / `Pile` / `BatchMap` 四张场 + `List<CarveMark>`。
看/擦/描/拓/对/量 全部读写它，所以手感天然一致。

**第一章的题眼（拓片会把改动一起带走）是数据模型的必然结果，不是脚本规则**：
磨改在 `Height` 里就是"某一段被重新凿过"，拓片整层转印，自然同时带走改动和改动前的痕迹。

## 四、踩过的坑（都花了不少时间，别再踩）

| 坑 | 现象 | 正解 |
|---|---|---|
| `Font.GetCharTexture` | Godot 4 C# 没有这个 API | 用 `SubViewport` + `Font.DrawString` + `GetTexture().GetImage()` 读回 |
| ★ 槽位名匹配不上文件名 | `logo_team` 匹配不到 `logo_team.png` → **所有美术槽位静默走程序兜底** | 槽位名默认补 `.png`；匹配失败再试一次。★ 这个 bug 只在"美术真的交了图"时才暴露，所以**必须做端到端验证** |
| 接缝检测用「首末两列逐像素比差」 | 把白噪声全判成有接缝 → 触发镜像折叠 → 毁掉一半刀口纹理 | 逐像素比对**对白噪声毫无意义**。真接缝是系统性的；而且这道修正**只对美术交的图做** |
| `TextServer.FontRenderGlyph` | C# 绑定里**返回 void**，只烘缓存不给你像素 | 得再从 `FontFile.GetTextureImage` 里读回来 |
| `FontFile.GetGlyphIndex(0, ...)` | 报 `p_size.x <= 0` | 第一个参数是**字号缓存下标**不是字号；下标 0 对动态字体是空的。要先 `FontRenderRange` 再用下标 1..N |
| `GetGlyphOffset` | 拿回来的是一条杂散色带不是字 | 它是**相对基线的偏移**，不是图集里的左上角。别用这条路 |
| SubViewport 同步读 | 永远读到空图 | SubViewport **下一帧**才渲染，必须 `await` 至少 2–3 帧 |
| `--headless` | SubViewport / DrawString 全都不出像素 | headless **没有渲染管线**。烘焙要带窗口跑，诊断要读已烘好的 PNG |
| `Math.PosMod` / `Math.FloorDiv` | .NET 里不存在 | 自己写或用 `Mathf` |
| `int a = 0, b = false;` | CS0029 | C# 不允许混合类型多变量声明 |
| `float edgeRight` 当 `bool` 用 | CS0029 | 三元表达式结果是 float，别直接 `if` |
| `x is > a*b and < c` | CS9135 | 模式匹配不能用非常量表达式 |
