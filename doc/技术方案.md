## 1. 我理解的项目意图

### 1.1 这不是一个推理游戏，这是一个关于「记录」的黑色喜剧

表面上它讲谋杀与骗保，实际上它的主角是**一本账**。

- 陆昀没有侦探天赋，没有背景，没有资源。他唯一的特殊之处是**他记账**。
- 全篇的对手不是苏航，是**纸与石头的可靠性差**：苏航能改纸，能磨石头，唯独改不了"某个人曾经忠实地记下过什么"。
- 结局无一例外都是**同一个问题的不同答案**：这个东西你留不留？
  - BE5 磨掉 → 留着石头，毁掉记录
  - BE6 报警 → 交出记录，石头消失在证物室
  - HE 砸底座 → 记录和石头并排，让所有人一起看见
- 最后一段「你们这个本子记了有啥用处」「石头不会撒谎，我得替它记着」「哦」——**主题落在一个「哦」上**。

所以整个游戏的技术目标只有一个：

> **让玩家自己产生一个"我记下了它"的冲动，并让这个冲动变成一个可以按下去的东西。**

技术方案里所有的机制设计，都是为了服务这一句。

### 1.2 三条不可让步的红线（我按蓝本继承）

| # | 红线 | 技术含义 |
|---|---|---|
| R1 | 不做「调查 / 思考 / 出示 / 对话选项」四个按钮 | 交互系统里**不存在**"点击热点"这个交互原语。所有信息必须由连续输入（按住拖动）产生。 |
| R2 | 系统不出声说"你发现了" | 全篇**零 HUD 文本**。唯一的动态文字是玩家自己抄进账本里的东西，和纸面上本来就有的印刷字。 |
| R3 | 没有 BGM，音效即反馈 | 音频只做一次性事件音（石屑、纸、尺）。不用任何循环音轨。 |

### 1.3 一个我认为需要重新确认的核心立意（重要）

蓝本里有一句反复出现的话：**"石头是唯一不会撒谎的东西，所以他得替它记着"**（剧情 2 章 / 终章）。

但按蓝本的物理设定，**被磨改的那块石头，正是那块在撒谎的石头**。如果照字面用这句话，主题会退化成"石头作证"——很常见、很弱。

我建议把这句话改成它更狠的那一版：

> **"石头不会撒谎。石头只是不会替你圆谎——它只记你刻了什么，不记你想干什么。"**

于是整个游戏的核心反转变成：

> **唯一能指认凶手的那块石头，是唯一被人动过手脚的石头。**
> 而唯一没被动过手脚的，是那本谁也拿不到、但陆昀自己天天翻的破账本。

这条改动会让第二章从"账本和系统对不上"变成"**账本和系统严丝合缝，唯一说谎的是碑面**"——
既更符合玩法文档的原意（玩法文档 ch2 写的正是"系统两行和账本完全一致"），也让"记这个动作"获得了道德重量。

**这一条与第 9 节决策点 D1 绑定，请优先答复。**

## 2. 范围裁剪（GameJam 的生死线）

### 2.1 原计划 vs 实际

蓝本目标是：6 章、7 结局、6 动词、4–5 小时单周目、纯手工像素美术。

以 GameJam 的实际产能，**美术 + 交互手感打磨会吃掉 70% 的时间**，而剧情文字因为已经写完，几乎不花时间。
所以裁剪原则是：**砍章节数量，砍结局数量，绝不砍交互原语的质量。**

保留四段，缺的部分用**一屏黑底白字**过渡（保留原文的句子，不用演出）：

## 4. 核心技术方案：表面数据模型

这是整个方案里最重要的一节。蓝本的六个动词（看/擦/描/拓/对/量）之所以能"手感一致"，是因为它们**本来就应该作用于同一个东西**。所以我们只做一份数据，六个动词都读写它。

### 4.1 数据模型

```csharp
// 一张"表面"= 三张同分辨率的单通道场 + 一份刻痕元数据
class SurfaceModel
{
    byte[] Height;   // 0=石面原高, 255=刻得最深
    byte[] Dust;     // 覆盖物厚度：石粉 / 锈 / 涂改液 / 灰
    byte[] Pile;     // 被擦下来的碎屑堆积
    List<CarveMark> Marks;  // 每一笔的"物理档案"
}

class CarveMark
{
    Vector2[] Points;   // 这一笔的走刀折线
    int   WidthPx;      // 字口宽度（2mm）
    int   Depth;        // 深度
    int   Roughness;    // 刀口毛边强度  ★新旧之差主要靠这个
    int   PitchSign;    // 石粉堆积方向
    int   BatchId;      // ★ 批次号：0=陆昀 2021-05-17, 1=苏航的补刻, 2=激光新碑
    Rect2 Bounds;
}
```

`BatchId` 就是"这一笔是哪一年刻的"。**它不参与任何判定逻辑，只参与渲染**——这是遵守 R2 的关键：数据里带着真相，代码不去解释它。

### 4.2 像素 × 放大镜的兼容（关键论点）

玩法要求"放大 3–4 倍，看的是质地不是形状"，同时要求像素风。直接放大位图会毁掉像素风。

**解法：放大镜不是"放大图像"，而是"显影另一个图层"。**

把石面拆成两层，**两层都是 640×360 原生像素**，同分辨率、无缩放：

- **BaseLayer**：字形块面 + 大面积明暗。远看（1×）就能读出字。
- **DetailLayer**：1:1 的高频信息——刀口毛边、石粉堆积、纤维走向。**在 1× 下人眼物理上分辨不出**（这是事实，不是设计选择），但在 4× 下清清楚楚。

放大镜做的事情只有一件：**在 4× 放大窗口里只显示 DetailLayer 的高对比版本**。
于是"靠质地分辨新旧"这个玩法要求，和像素画的分辨率限制**不再冲突**——反而是分辨率限制在帮你：**玩家必须凑近才能看**，这正是石刻匠的动作。

`Roughness` / `PitchSign` / `Depth` 如何映射到 DetailLayer 的像素，由 `StoneSurface.gdshader` 负责（灰度噪声 + 各向异性条纹，用 `BatchId` 选不同的噪声种子与相关长度）。**这样"新刻 vs 旧刻"的视觉差异是程序生成的，不需要美术画两套字**，迭代极快。

美术只需要提供：**字形块面图 + 一张通用石材噪声 + 一份 Brush 笔刷**。这是像素美术成本能压到 3–5 小时的关键。

### 4.3 六个动词的实现契约

全部是 `Control`，全部只看鼠标，不看剧情。统一签名：

```csharp
abstract class VerbControl : Control
{
    public SurfaceModel Target { get; set; }
    public event Action Progress;          // 阶段完成
    public virtual bool BlocksCamera { get; }
}
```

| 动词 | 输入 | 数据行为 | 失败/代价 |
|---|---|---|---|
| **看**（Loupe） | 移动鼠标 | 只读，切 DetailLayer 高对比 | 无 |
| **擦**（Brush） | 按住右键拖动 | `Dust -= rate·dt·falloff`；`Pile += 擦掉量`（画在笔画两侧） | `Dust < 阈值` 后继续擦 → 把 `Pile` **压进 `Height`**（局部降低），该处 DetailLayer 对比度永久下降。**"擦过头"不是计数器，是一个物理后果。** |
| **描**（Tracer） | 按住左键拖动 | 记录路径 → 实时算到 `CarveMark` 的距离 | 偏离容差 → **断笔**，必须从上一个断点重来（不是从头，是从断点——这就是"从断点重来"的实现） |
| **拓**（Rubber） | 选纸 → 覆纸 → **按住左键有节奏地敲** | 每次敲击：`PaperAlpha += (Height > 阈值) ? click : 0` | 累计超阈值 → 向邻域扩散（糊成一片）。**没有进度条** |
| **对**（Overlapper） | 拖动一张纸到另一张上 + 按住右键举到光下 | 两张 PaperDoc 的 alpha 合成；折痕/裁边/印痕是独立图层 | 对齐折痕 → 记 flag |
| **量**（Caliper） | 拖动卡尺 + 滚轮微调 | **只显示读数**。判定在章节层 | 无 |

**"擦"没有次数成本，只有覆盖率**——这样玩家的体感是"我擦得不够/擦过了"，而不是"我还有 2 次机会"。次数成本是 UI 语言，覆盖率是物理语言，后者更符合这个游戏的气质。

### 4.4 拓片：唯一能把证据带走的东西

`Rubber` 完成后产出一个 `Evidence`（拓片）。它的关键性质：

> **拓片是把 `Height` 场整层转印下来的，包括被磨改的部分。**

因为磨改在 `Height` 里就是"某一段被重新凿过"——`BatchId` 变了，但形状还在。所以**拓片天然同时包含"改动"和"改动之前的痕迹"**，第一章的题眼（拓片 vs 清碑）自动成立，不需要任何脚本特殊处理。

**这是本方案里我最满意的一处设计**：题眼不是我写出来的规则，它是数据模型的必然结果。

### 4.5 账本即存档（Save System = Ledger）

蓝本说"账本的厚度就是玩家的进度"。把它做成字面意思：

```csharp
class RunState                     // 存档 = 这个对象，序列化为 user://save.json
{
    List<LedgerPage> Pages;        // 玩家抄下来的每一页（内容 + 抄写时间戳）
    HashSet<string> Flags;         // 见下
    List<Evidence> Carried;        // 拓片、复印件
    Dictionary<string,int> Misc;   // 擦过头次数、撕页记录……
}
```

必须记的 5 个数据（蓝本第十三节）+ 我加的 2 个：

```
ledger_backnote_read   账本第一页背面那行"厚料立碑…"是否读过   ★ 终章 HE 的开关
rubbing_carried        第一张拓片是否还在身上
page_torn              第二章翻页是否撕过
ch04_answer           第四章选了哪个回答（4 值）
over_wiped_count       擦过头次数
deed_cached            第五章是否把两个日期并排抄下来
base_exposed           终章底座是否已被砸开
```

序列化用 `System.Text.Json`（Godot C# 自带），**不接入任何节点树**。这样"读档"不是游戏系统，只是一个还原 `RunState` 的动作；而且**没有传统意义的存档点**——玩家不能回退，这与 R1 一致。

## 5. 章节实现要点（只讲难点）

### 5.1 第一章「看字」——四段递进的可判定化

蓝本的四段里有几处描述是含糊的（见 D4）。我的建议（同时也是需要编剧确认的部分）：

先把物理事实摆清楚，让"名字"和"日期"两条改动各自有唯一形态：

| 段 | 玩家在找什么 | 判定 | 为什么玩家能自己发现 |
|---|---|---|---|
| 一 | 「梅」字**最后一横** | 该笔的 DetailLayer 覆盖率 ≥ 55% | 这是 **Batch 1**（补刻），`Roughness` 明显低于同一字的其他笔 |
| 二 | 木字旁的**那一竖/撇** | 该笔覆盖率 ≥ 55% | 也是 Batch 1。这一竖与「韩」字上同类笔画**笔法一致**——因为它们是**同一把錾子同一只手刻的**，改碑的人和陆昀用的是同一个型号的錾子（甚至就是那把借出去的） |
| 三 | 「六」底下的**「七」** | 先擦开（Dust 清零）再描出磨痕轮廓 | 「十」被往左挪了 2mm，所以**字距是唯一不用擦就能看见的线索**——这是给玩家的第一级台阶 |
| 四 | 拓一张片子 | 敲击累计 ≥ 阈值且未糊 | 无 |

**这里我要加一个蓝本里没有的东西：工具箱里的练手料头。**

一块巴掌大的废山西黑，上面是陆昀自己随手刻的一行废字（"陆氏石刻"试刻），**同一把錾子、同一双手、同一个手法**。

它的作用只有一个：**给玩家一个"新刻"的样本**。
玩家可以先在料头上看到"陆昀刻的刀口长什么样"，再回到碑上比"这一笔也是这个刀口"。

没有它，玩家的真实体验是"三笔里有一笔不一样，但**我凭什么知道哪一笔是新的**"——他不知道什么叫新刀口。设计文档说"宁可让玩家卡十分钟"，但**卡十分钟和卡到放弃是两件事**。加一块料头，难度从"猜作者意图"降到"做对比"，而"对比"正是这个游戏想教的动作。

这是我认为**投入产出比最高的一处设计增补**（美术成本：一块小图 + 复用同一套 DetailLayer 参数，1 小时内）。

### 5.2 终章「你的锤子」——HE 的开关必须在前面拿到

剧情里 HE 的关键物证是：碑底下压着**陆昀半年前交到墓园存档室的一份复印件**（原始材料：五月十七）。

**但蓝本的玩法里没有任何一个"交复印件存档"的动作。** 这是断链。

修复（建议）：在第五章档案室里，玩家拿到那份复印件之后，桌面角落有**墓园档案室的存档登记表**（蓝本玩法文档 ch5 提到过"档案室"）。玩家把复印件拖到登记表上 → 登记表盖章 → `deed_cached = true`，复印件进 `Carried`。

这样：
- HE 需要：`ledger_backnote_read`（知道要砸底座）**+** 砸底座 → 底座下露出他自己的刻字 + 他身上/档案里的复印件形成对照。
- **玩家如果有复印件但没读账本背面** → 砸得开，但露出的证据只有"两行十七"，还需要复印件才能构成"同源对照"，媒体效应弱 → 可以设计成一个**弱化版 HE 尾声**（放文本，不放演出）。这是极好的"你做了 90% 但漏了一步"的负反馈，不需要新章节。

同时这也让"第四章吓着苏老师 → 第五章不让你靠近"的惩罚有了具体落点：**档案室工作人员不让你碰登记表**，你就拿不到复印件。

### 5.3 第二章的"自由输入"要有宽松匹配

玩法要求玩家**手抄**碑面日期作为过关条件。自由输入是 Jam 里最容易翻车的地方（玩家打 `2021/5/16`、打 `16号`、打汉字数字）。

`DateNormalizer.Normalize(string) -> (int? year, int? month, int? day)` 接受：
- `2021-05-16` `2021/5/16` `2021.5.16` `2021年5月16日` `五月十六日` `5.16` `16号` `十六`
- 汉字数字转换表（〇一二三四五六七八九十 → 0..10，含"十六"=16 这种组合读法）

过关条件：**玩家写下的日期里，月和日与"十六"一致**（年份可省）。空格、全角半角、破折号全忽略。

这样既保留了"手抄"的手感（他得回碑那边看一眼），又不会因为输入法把玩家卡死。

### 5.4 第四章：不要选项框

蓝本说这章"对话是资源不是选项"，四种回答后果不同。我的实现：

- 屏幕上只有**苏老师的背影**（轮椅侧后方视角，她凑近碑面）。**没有任何 UI 元素。**
- 屏幕底部出现一行文字提示可以回复，然后**输入行自己消失，5 秒倒计时开始**（不显示数字，只有一个字的呼吸感）。5 秒内不说话 = 第三种回答（沉默）。
- 玩家从键盘直接打字。**输入框是无边框、透明、和碑面同一个视觉层。**
- 打出的字**直接变成碑面上的字**（她的手指停在碑上）。

这样"不说话"是一个**主动选择**而不是"什么都没点"——它在 UI 上和另外三种平级，玩家不会因为"找不到第四个按钮"而困惑。这是把 R1 贯彻到底的做法。

### 5.5 终章的 90 秒演出（成本控制）

蓝本要求：不可跳过、不可加速、镜头锁死、只有水泥碎屑的声音。

实现成本极低，因为**不需要角色动画**：
- 镜头固定俯视底座。
- 一个 `Chisel` 动词：按住左键 → 水泥层 `Cement[i] -= rate·dt`。
- 露出的进度**通过画面本身表达**：水泥碎片以粒子落到地上（纯 GPU 粒子，无骨骼动画）。
- 每 8 秒一次轻微的镜头位移（抖动 1 像素），模拟手上用劲。
- 音频：只有 `cement_chip` 循环（这是**唯一一个允许循环的音**，因为它是"持续动作"而不是氛围）。
- 底下那层小字在 `Cement` 降到阈值时通过 DetailLayer 显影出来。

**这条曲线是全篇情绪最高点，所以它值得独占 15 分钟实现，但只需要 15 分钟。**

## 10. 附：两份蓝本的矛盾清单（这是 D4 的内容）

我在通读时逐条核对了数字与因果，以下 **7 处是硬矛盾**（不是风格问题，是会导致游戏跑不通 / 玩家推理失败的问题）。

### 矛盾 1 · 账本上的日期到底是 16 还是 17 —— **最严重**

- `剧情.md` 第一章：陆昀登记 **材料日期 2021-05-16 / 刻字日期 2021-05-16**，且"两行都是十六"。
- `剧情.md` 第二章：系统里是 **17 / 17**，"他记得…他没记错，材料上明明写的是十六号"。
- `剧情.md` 终章 + 真相 + HE：**他自己刻的是 17 / 17**（"底下那层石头…是他半年前刻的：材料日期 2021-05-17"）。

三处互相冲突。

**建议统一为 17**（因为真相是"原始材料上写的是十七"，苏航事后把碑面磨成十六）：
> 委托单上是「韩梅，五月十七日卒」→ 陆昀照着刻 17，账本写真话 17 → 苏航磨碑面成 16，改所有纸 → **碑面是唯一说谎的石头**。

这同时让 `玩法设计.md` 第二章的原意成立（它写的是"账本 17 / 系统 17，完全一致，唯一对不上的是碑面 16"）。

### 矛盾 2 · `剧情.md` 第二章 "没人改系统"，但系统里姓名已经是"韩梅"

若原碑刻的是「韩湘」，系统里必然已经被改过姓名了。所以"没人改系统"要么改口，要么改成**系统里有两条记录**：
> `经办登记`（陆昀签署，只读，17/17）+ `墓位信息`（墓园可改，苏航把姓名改成了韩梅）

后者更好：它解释了苏航为什么漏了日期（**他只改了他能改的那条**），也解释了为什么"只记时间不记人"的系统会漏。

### 矛盾 3 · `玩法设计.md` 第四章写成"**老吴**手里没有证据"

全文主角是陆昀，没有"老吴"这个人。笔误，建议全文替换为"陆昀"。

### 矛盾 4 · 终章"砸碑面"映射到 BE4，BE4 里根本没有砸碑面

`玩法设计.md` 终章说"砸碑面 → 砸的是新碑，什么也证明不了 → **BE4 签字**"；
但 `剧情.md` 的 BE4 是**老樊带人来让他签情况说明**，从头到尾没有锤子。

**建议**：终章改为三个动作 → 砸底座（HE）/ 放下锤子打电话（BE6）/ **站着不动**（BE4 证人）。
把"砸碑面"删掉——它既不产生新信息，也毁了现场，还会让玩家以为游戏有"错误选项"。**这个游戏里不该有错误选项。**

### 矛盾 5 · HE 需要一份"存档室复印件"，但没有任何章节让玩家拿到它

见 5.2。建议在第五章加一个"把复印件放上存档登记表"的动作。

### 矛盾 6 · 保险条款不成立

原文：*"日期从十七改成十六，因为十六号在等待期之外，十七号不在。"*
投保日不明，则无法解释为什么偏偏卡在 16/17 之间一天。

**建议钉死一个日期**（这是全篇最需要的"硬"）：
> 保单投保日 **2020-11-17**，条款"等待期 180 日"。→ **2021-05-16** 是等待期最后一天。
> 十六 = 全额赔付；十七 = 只赔 30%。

改动只有两行，但"16 和 17 之差"从此有了不可辩驳的依据。**这是把整个诡计从"作者 conveniently 选的数字"变成"制度造成的悲剧"的关键一步。**

### 矛盾 7 · 第三章"三张纸上的日期都是十六"，但同章明写火化证是十七

原文自己写了火化证是"五月十七日火化"。

**建议改为**：
